# ダビスタ2 牧場ノート

Nintendo Switch 2版『ダービースタリオン2』向けの配合確認・探索・所有馬管理を行うWebアプリです。
React / TypeScriptの画面と、Hono / SQLiteのローカルサーバで動作します。
自宅内などで動作させることを想定しており、公開した場合の動作は未確認です。また、各種データには間違いがある可能性があります。

## 主な機能

### 配合確認・探索

- 父と母を選び、産駒の血統表、成立する配合理論、クロス・因子、ニックスを確認できます。
- 1世代の総当たりは繁殖牝馬・種牡馬のどちらからでも開始できます。数世代にわたる配合経路や、種牡馬を繰り返し使うループ（凝った配合ループ）も探索できます。
- 配合理論、欲しい因子・避けたい因子、クロス本数、種牡馬の能力などを条件にできます。数世代探索では配合回数・種付料の上限や、途中・最後に使う種牡馬も指定できます。
- 結果は並べ替えや種牡馬による絞り込みができ、そのまま配合確認や計画の保存へ進めます。数世代・ループ探索は、画面を離れても続くサーバ側のバックグラウンド実行に対応しています。

### 配合計画・所有馬

- 探索で見つけた配合経路を計画として保存し、実際に生産した所有馬と紐付けられます。計画上の馬と所有馬は別々に管理し、1頭の所有馬を複数の計画に対応づけられます。
- 所有馬の区分、基本情報、血統表、能力・因子、写真、メモ、戦績を登録・編集できます。
- 戦績はレースデータから選んで登録でき、新馬戦・未勝利戦・条件戦も選択できます。競馬場、芝・ダート、距離、馬場状態、着順を記録し、レースの格や着順を色分けして表示します。

### データの閲覧・編集

- 種牡馬・繁殖牝馬・祖先・凝ったペア・ニックス・レースを検索し、登録内容を編集できます。
- 種牡馬・繁殖牝馬の一覧で能力や評価を比較し、列見出しから並べ替えられます。詳細はダイアログで開けます。
- 馬名検索はひらがな・カタカナの表記揺れや、登録済みの英名の日本語読みに対応しています。

### 写真からの取り込み

- 育成馬・入厩馬・血統・種牡馬・繁殖牝馬などのゲーム画面を読み取り、登録・更新できます。
- 種牡馬の一覧画像からも種付料や能力を読み取り、変更前後を確認して項目ごとに反映できます。種付け画面のニックスは、繁殖牝馬を指定して相性表に記録できます。
- 複数枚をまとめて送り、解析中は別の画面で作業できます。対応するAPIを設定すると、所有馬の画像も切り出して保存できます。

### 牧場設定・AIによる命名と読み物

- 牧場名と冠名を設定できます。冠名は牡牝共通・別々を選び、馬名の前後どちらに付けるか指定できます。
- 未命名の所有馬には、父母の情報・自家生産馬の戦績・3代の血統表などをもとに、由来付きの命名候補を5つ生成できます。冠名を設定している場合は、冠名付き3案と冠名なし2案を提案します。
- 「愛馬の一篇」では、戦績・血統・能力・メモをもとに、その馬の歩みを綴る読み物を生成できます。命名済み・デビュー済みの3歳以上が対象で、文体の選択、文章の編集、HTML保存、印刷・PDF保存に対応しています。

写真の読み取り・命名候補・「愛馬の一篇」の生成には、APIの設定が必要です。

### 同期・セーブデータ

- 同じサーバにつないだ複数端末で、所有馬・計画・設定などを同期できます。
- 最大5件のスナップショットを保存し、確認ダイアログを経てその時点の状態へロードできます。ゲーム内のセーブ・ロードに合わせた試行錯誤や、JSONによるバックアップにも対応しています。

## 起動

Node.js 24系とnpmを使用します。
依存パッケージの取得先は `.npmrc` に設定しています。

```bash
npm ci
cp .env.example .env
npm start
```

ブラウザで `http://localhost:8877` を開きます。
同じLANの別端末からは `http://<サーバのIPアドレス>:8877` にアクセスできます。

`.env` の主な設定は以下のとおりです。
実際のAPIキーや認証トークンは `.env` に保存し、Gitには含めません。

| 変数 | 用途 |
|---|---|
| `PORT` | サーバのポート（既定: `8877`） |
| `DS2_DB` | SQLiteの保存先（既定: `server/data/ds2.sqlite`） |
| `DS2_TOKEN` | APIの認証トークン。設定した場合は各端末の同期設定にも入力 |
| `LLM_API_KEY` | 写真読み取り・命名候補・愛馬の一篇に使うAPIキー |
| `LLM_BASE_URL` / `LLM_MODEL` | 上記のAI機能で使う接続先とモデル（既定値は `.env.example` を参照） |
| `SAM_MODEL` | 馬の画像切り出しに使うモデル |

AI機能には、`response_format: json_schema` に対応したOpenAI互換Chat Completions APIを使用します。
写真読み取りには画像入力への対応も必要です。
写真や、生成に使う対象馬・血統・戦績などの情報は、設定したAPIに送信されます。
APIキーが未設定でも、配合確認・探索や手動での登録・編集は利用できます。
馬の画像切り出しはMetaのSAM対応APIを使用します。
`DS2_TOKEN` が空の場合、APIは認証なしで動作します。

## 開発・検証

APIサーバと画面の開発サーバを、それぞれ別のターミナルで起動します。

```bash
npm run server:dev
```

```bash
npm run dev
```

画面は `http://localhost:5173` で開き、`/api` は `8877` 番のサーバへ転送されます。

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

## データの保存

所有馬・計画・設定・データの編集はサーバのSQLiteに保存され、ブラウザにもキャッシュされます。
写真は `server/data/images/` に保存されます。
設定画面から、最大5件のセーブ・ロードとJSONバックアップを利用できます。
ロードは現在の状態を置き換え、接続している他の端末にも反映されます。

JSONバックアップには写真とサーバ上のセーブデータを含みません。
サーバを移す場合は停止してからSQLiteと画像ディレクトリをまとめて保管してください。
保存先を変更した場合も、利用者データはGit管理の対象に含めません。

## リポジトリの構成

| パス | 内容 |
|---|---|
| `src/core/` | 配合判定・探索・データ処理 |
| `src/ui/` / `src/store/` | 画面とクライアントの状態管理 |
| `data/data.json` | 馬・血統・凝ったペア・ニックス・レース・検索別名をまとめたマスターデータ |
| `src/data/` | マスターデータの読み込みと画面用の定義 |
| `server/` | API・同期・画像読み取り・バックグラウンド処理 |
| `test/` | 自動テストと必要なフィクスチャ |
